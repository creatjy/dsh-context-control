## 一、需求文档

### 1.1 背景

DSH 每一轮请求都会重发「系统提示 + 技能目录 + 工具说明 + 工具定义」。默认组合下：

- 单轮固定开销可达 40k tokens 以上，其中工具文档占大头（github 14,425、agent-teams 8,958、mcp-connector 5,207）；
- 长会话里工具结果、助手消息持续累积，窗口压力上涨，但用户看不到「钱花在哪」；
- DSH 自带压缩是黑盒：压了多少、压完窗口多大、压缩为什么失败，都不直观；
- 用户想关掉某个能力时，缺少「加载 / 简介 / 隐藏」这种档位，只能全有或全无。

插件要解决的就是这四件事：**可观测、可裁剪、可压缩、可验证**。

### 1.2 目标与非目标

**目标**

1. 把一次请求的上下文拆成模块，逐块给出 token 估算，且能逐块开关。
2. 支持分层作用域：模式规则 → 全局层 → 项目层（按会话 cwd 自动匹配、可继承）→ 会话层（胶囊里的临时覆盖）。
3. 会话内提供胶囊：实时窗口占用、模块构成、生成压缩指令、执行压缩、展示压缩结果。
4. 压缩走宿主真实压缩服务，而不是只给模型发一段「请压缩」的文字。
5. 所有改动可逆：随时切回「完整上下文」模式做对照。

**非目标**

- 不替代 DSH 自身的记忆 / 检索 / 会话存储；
- 不修改模型可见的系统提示语义（只删、只附简介，不凭空加指令）；
- 不做跨 profile 的同步或多用户协作。

### 1.3 用户与典型场景

| 角色 | 场景 | 期望 |
| --- | --- | --- |
| 日常使用者 | 会话变慢、变贵 | 一眼看到大头，一键精简 |
| 多项目开发者 | 不同仓库需要不同能力 | 按 cwd 自动套用项目规则 |
| 调试者 | 压缩失败 | 看到真实原因，而不是「忙」 |
| 插件作者 | 宿主升级后回归 | 有诊断接口、可降级 |

#### FR-01 细节

- 请求侧四组：系统内容、技能、工具说明、运行时注入；工具定义单独成表。
- 估算规则：CJK ≈ 1 字 1 token，其余 ≈ 3.6 字符 1 token；只用于「这次要发多少」的相对判断。
- 会话侧不估算，直接读 `tokenMeter.measure()`。

#### FR-05 细节

- 窗口占用取 `tokenMeter.contextPressure().pressureTokens`，与 DSH 状态栏一致。
- 日志累计取 `measure().totalTokens`，包含已被压缩掉的历史，所以通常大于窗口占用。
- 分模块明细按「窗口是日志尾部」切片：从最新往前累到窗口占用为止。

#### FR-07 细节

- 宿主压缩只允许空闲 agent；忙时返回排队，不丢用户点击。
- 压缩结果必须包含：`compacted`、`shadowedTokens`、`beforeTokens/afterTokens`、`beforeSurface/afterSurface`、`via`（service / command）、失败原因。

#### FR-08 细节

- 排队项 10 分钟过期，避免会话关闭后永远挂着。
- 自动压缩同一时刻只跑一个（`compactBusy`），避免抖动。
- 阈值存 `modes.json` 的 `autoCompact.ratio`，默认 0.8，可配范围 5%–95%；UI 输入越界时按边界值显示并提交。

### 1.6 约束与假设

1. 宿主 `compactNow` 要求 agent 真正空闲；「忙」是宿主侧的硬约束。
2. `compactNow` 内部调用 `agent.runMaintenance(...)`，因此必须传**真 agent**，不能传 `{session, options}` 合成对象。
3. 插件包位置变化（link 路径变化）需要重启应用才能完全生效；纯 JS 改动可通过禁用/启用插件重载。
4. 客户端 bundle 由宿主加载，改 `client.js` 后通常需要刷新页面。
5. 系统提示每次变化都会追加一份完整副本，这是 DSH 的既有行为，插件只能减少触发频率，不能改宿主协议。

## 二、技术方案

### 2.1 总体架构

```
┌──────────────────────────── Client（Web GUI）────────────────────────────┐
│  Panel（构成 / 项目 / 全局）   ComposerChip（概览 / 技能 / MCP / 插件 / 提示段 / 工具） │
│   - 模块表、开关、编辑                - 窗口占用、分块明细                     │
│   - 项目继承链、一键精简              - 压缩指令、立即压缩、上次压缩            │
└───────────────────────────────┬──────────────────────────────────────────┘
                                │ HTTP  /dsh-context-control/api
┌───────────────────────────────┴──────────────────────────────────────────┐
│ Host 插件（Cordis）                                                        │
│  apply(ctx)                                                                │
│   ├─ store（modes.json：模式/全局/项目/会话/autoCompact/lastCompact）       │
│   ├─ 目录：capabilityCatalog → capPlan（能力键/档位/待删段与工具）           │
│   ├─ 投影：projectRequest（与装配同款规则）→ projected/removedTokens        │
│   ├─ 装配：promptFor → 规则裁剪 → applyCaps → brief → attachTools          │
│   ├─ 计量：tokenMeter.measure / contextPressure；tokens.js 估算            │
│   ├─ 压缩：resolveCompaction → compactSession → 服务或 /compact            │
│   ├─ 调度：setInterval 8s tickCompaction；session/event turn/end          │
│   └─ HTTP actions（见 2.8）                                                │
└───────────────────────────────────────────────────────────────────────────┘
```

分层职责：

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 规则层 | 决定每个能力「加载 / 简介 / 隐藏」 | 不生成提示词正文 |
| 目录层 | 扫描技能目录、MCP 工具、插件工具、系统提示段 | 不决定开关 |
| 装配层 | 按规则删段、留简介、附加工具定义 | 不改写模型输出 |
| 计量层 | 请求侧估算 + 会话侧真实统计 | 不持久化 token |
| 压缩层 | 找服务、判空闲、执行、记录结果 | 不决定窗口阈值（读配置） |
| UI 层 | 展示与交互 | 不直接读宿主服务 |

### 2.2 能力键（capKey）与作用域

能力键是「开关的最小单位」：

- 技能：`skill:<name>`（来自系统提示里的 `- skill:名字 — 摘要` 行）
- MCP：`mcp:<server>`（`mcp__<server>__<tool>` → `mcp:<server>`）
- 插件：`plugin:<pluginId>`（工具名按归属插件映射）

`capKeyOfTool(name)` 的实现（`lib/index.js:371`）：

```js
const server = mcpServerOfTool(toolName);
if (server) return `mcp:${server}`;
const plugin = pluginOfTool(toolName);
return plugin ? `plugin:${plugin}` : null;
```

生效顺序（后者覆盖前者）：

1. 模式规则（`mode.rules`，内置「完整上下文 / 上下文管控」两套）
2. 全局层（`state.global.caps/sections/tools`）
3. 项目层（按 cwd 匹配项目，沿 `parentId` 继承，再叠加自己的档位）
4. 会话层（胶囊里的技能/MCP/插件、系统提示段、系统工具覆盖，存 `state.sessions[sessionId]`，只影响这条会话）
5. 会话内「本次放行」（`awakeSet`，只影响当前请求）

### 2.3 三种档位与「保留简介」

| 档位 | 系统提示段 | 工具定义 | 效果 |
| --- | --- | --- | --- |
| 加载 | 保留 | 保留 | 默认 |
| 简介 | 保留一行摘要 / 目录行 | 删除完整 schema，保留一行说明 | 省 token，仍让模型知道存在 |
| 隐藏 | 删除整段 | 删除 | 最省，模型完全不知道 |

「保留简介」对应 `state.brief.enabled`（全局开关），摘要来自 `lib/capabilities.js` 的解析结果或手写 brief。

### 2.4 三种数字口径（别混着看）

| 数字 | 来源 | 含义 | 出现在 |
| --- | --- | --- | --- |
| 窗口占用 | `contextPressure().pressureTokens` | 这一轮真正带进模型的历史 | 胶囊、会话卡片 |
| 日志累计 | `measure().totalTokens` | 会话日志总量（含已折叠） | 卡片副标题 |
| 本次请求 ≈ | 字符估算（CJK 1:1，其余 3.6:1） | 系统提示 + 技能 + 工具说明 + 工具定义 | 面板顶部 |

窗口是日志的尾部：从最新一条往前累到窗口占用为止，分模块明细按这个边界切，所以「工具结果 + 助手消息 + 用户消息」之和等于窗口占用。

胶囊「概览」里有两个组，加起来不是当前占用：

- **会话已累积** ≈ 当前窗口（胶囊与 DSH 显示的就是它）；
- **每次请求都会重发** 是下一轮还要额外发的系统提示与工具定义，按本会话/项目规则与能力开关投影（0.5.15 起已扣掉隐藏项，并计入关闭项简介）；
- 两个相加 ≈ **下一轮预计**，只是粗估，不能当成现在的窗口。0.5.13 起胶囊顶部直接列这三个数并加了说明。

0.5.15 起，「每次重发」不再拿原始 prompt 直接相加，而是服务端 `projectRequest()` 按真实装配顺序算出的投影：

```js
const rules = mergeCapRules(effectiveRules(store), plan);
const merged = mergeScopeRules(rules, layers);
const next = withBrief(applyRules(prompt, merged), brief);
```

- `projected = { total, sections, contexts, tools, removed, removedTokens }`；
- `removedTokens` 按 `removed.sections / contexts / tools` 三类分别累加原始 token，概览的「少发」与胶囊说明都读它；
- 工具 token 优先用宿主快照里的 `tool.tokens`，缺失时才退回 `lib/prompt.js` 的 `toolTokens()` 估算。早期只用后者，147 个工具算成 13,035，而宿主同口径是 37,979，差近 3 倍；
- 能力被设为「隐藏」时 `plan.items` 可能为空，但 `plan.sections/tools` 仍有内容，`mergeCapRules` 不能因为 items 为空就提前返回（0.5.15 修）。
- 工具裁剪的落地时机（0.5.28，0.5.29 修正旧工具名过滤）：宿主 `preStep` 先 `tools.resolve()` 再 `systemPrompt.assemble()`，在 assemble 里才 `tools.restrict()` 只能影响下一步。现在改为在 `agent/created` 时调用 `bindCapabilityRestriction()`，读取 cwd/项目/能力计划并立即挂 `agent.ctx.tools.restrict({ deny })`；assemble 仍复用同一 helper 兜底。

### 2.5 压缩流水线

```
用户点「立即压缩」/ 自动触发 / 排队到期
        │
        ▼
compactSession(runtime, sessionId, why)
        │
        ├─ resolveAgent(ctx, sessionId) → 真 agent（含 session）
        ├─ before = tokenMeter.measure(session)
        ├─ resolveCompaction(runtime, agent)
        │    1) agent.ctx 上的 compaction 服务
        │    2) 根 ctx 的 compaction 服务
        │    3) agentPresets.serviceFor(agent, "compaction")
        │    4) 都没有 → 记录 unavailable
        │
        ├─ 服务路径：compaction.compactNow(agent, signal)
        │    ※ 必须传真 agent：宿主内部会调 agent.runMaintenance(...)
        │    ※ 失败不立刻放弃，记 failures
        │
        ├─ 命令路径（服务没成 / 没有可压缩区间）：
        │    commands.execute(agent, "/compact", [], signal)
        │    ※ "No compactable history yet." 视为「没压」，不算失败
        │
        ├─ after = tokenMeter.measure(session)
        └─ 返回 {compacted, via, note, shadowedTokens,
                 beforeTokens, afterTokens, beforeSurface, afterSurface}
```

结果字段与含义：

| 字段 | 含义 |
| --- | --- |
| `via` | `agent`（服务）/ `command`（`/compact`） |
| `compacted` | 是否真的发生折叠；`false` 时 `note` 说明原因 |
| `shadowedTokens` | 被折叠掉的 token 数 |
| `beforeTokens/afterTokens` | 日志累计前后 |
| `beforeSurface/afterSurface` | 当前有效表面（窗口）前后 |
| `ratio` | 触发时的压力比（自动压缩才有） |
| `error` | 真实失败原因（服务与命令两条路径合并） |

**关键坑（已修）**：宿主 `dsh-compaction-basic/lib/index.js` 的 `compactNow` 是 catch-all，任何异常都会变成
`ManualCompactionError("busy", "manual compaction requires an idle agent with no waking queued work")`。
旧实现传 `{session, options}` 合成对象，`agent.runMaintenance is not a function` 被包装成「忙」，
看起来像空闲判断失效，实际是调用方式错了。0.5.11 起传真 agent，并保留 `/compact` 回退。

### 2.6 空闲判定与调度

```js
// 真 agent 上判断「这一轮是否还在跑」
agentsSvc.turnBoundaryOf(agent.session).openTurnStartSeq === null
```

三条触发路径：

1. **手动**：`POST {action:"compact"}`。若宿主返回忙，写入 `runtime.pendingCompact`，返回 `{queued:true}`。
2. **turn/end**：`ctx.on("session/event")` 收到 `turn/end` 后等 120ms 再试；失败且错误命中 `/idle|busy|waking/i` 时 1.5s 后重试，最多 3 次。
3. **轮询**：`setInterval(tickCompaction, 8000)`（`unref`，随 effect 清理）。
   - 先补排队项（优先于自动压缩）；
   - 再扫所有 root agent，`pressureTokens / contextWindow ≥ autoCompact.ratio` 且空闲 → 自动压一次；
   - `compactBusy` 保证同一时刻只跑一个。

为什么还要轮询：`session/event` 在插件重载、turn/end 与压缩窗口错位时可能漏掉；8 秒轮询是兜底，不是主路径。

### 2.7 状态与持久化

`modes.json` 顶层结构（`version: 3`）：

```jsonc
{
  "version": 3,
  "revision": 0,                   // 每次成功写入 +1；undoToken 用它检测配置漂移
  "activeModeId": "context-control",
  "brief": { "enabled": true },
  "autoCompact": { "enabled": true, "ratio": 0.8 },
  "ai": {                          // 0.6.0 规划：默认关闭，不隐式发送会话内容
    "enabled": false,
    "impactScan": "off",           // off | on；on 才允许额外一次影响分析
    "privacyAcceptedAt": null      // 隐私说明确认时间；null 时 AI 按钮不可用
  },
  "lastCompact": null,            // 最近一次压缩结果（白名单字段）
  "sessions": {},                  // 会话级覆盖：{ [sessionId]: { caps, sections, tools, updatedAt } }，只留最近 50 条
  "global": { "caps": {}, "sections": {}, "tools": {} },
  "projects": [
    {
      "id": "default", "name": "工作区默认", "cwd": "",
      "parentId": null, "builtin": true,
      "caps": {}, "sections": {}, "tools": {}
    }
  ],
  "modes": [
    { "id": "full", "name": "完整上下文", "builtin": true, "rules": {} },
    { "id": "context-control", "name": "上下文管控", "builtin": true, "rules": {} }
  ]
}
```

写入策略：

- `sanitizeState` 对每个字段做白名单与范围校验（`autoCompact.ratio` 0.05–0.95，越界回 0.8；`ai.impactScan` 只接受 `off/on`，缺失回 `off`；`revision` 非负整数，缺失回 0）；
- 项目父子关系断环，根项目必须存在；
- `revision` 只在整次事务成功后递增；AI 应用走 `store.transaction`/`applyOps`，全量校验 → 单次原子落盘 → 失败回滚，不允许 20 次 `writeFileAtomic` 的半写状态；
- `undoToken` 记录 `modeId` + `revision` + `scopeKey`；切模式或配置已变时拒绝撤销，不按当前 `active()` 硬写；
- `lastCompact` 只保留 `at/sessionId/why/via/note/compacted/summarySeq/shadowedTokens/beforeTokens/afterTokens/beforeSurface/afterSurface/ratio/error`；
- `sessions` 里每项可有 `caps`（技能/MCP/插件）、`sections`（系统提示段）、`tools`（系统工具）三张覆盖表，按 `updatedAt` 排序裁剪到 50 条；剪枝导致旧值缺失时，撤销返回 `partial`，不静默成功；
- 读取失败或文件损坏 → 回默认值，不抛异常。

### 2.8 HTTP API

入口：`/dsh-context-control/api`（GET 查询 / POST 动作）。

| action | 关键入参 | 用途 |
| --- | --- | --- |
| `session` | `sessionId` | 会话窗口明细、分块占用、压力 |
| `compact` | `sessionId` | 立即压缩（忙则排队） |
| `setAutoCompact` | `enabled`, `ratio` | 配置自动压缩 |
| `tick` | — | 手动催一次轮询 |
| `tickdiag` | — | 每个 agent 的空闲/压力诊断 |
| `diag` | — | 服务与运行环境诊断 |
| `check` | — | 规则/配置一致性检查 |
| `probe` | — | 探测宿主服务 |
| `prompt` | `sessionId` | 取当前装配后的提示词 |
| `inject` | `sessionId`, 指令 | 注入压缩指令到会话 |
| `activate` | `modeId` | 切换模式 |
| `createMode` / `renameMode` / `deleteMode` / `resetMode` | 模式字段 | 模式管理 |
| `createProject` / `updateProject` / `deleteProject` | 项目字段 | 项目管理 |
| `setRule` / `setScopeRule` | 规则字段 | 模式/作用域规则 |
| `setCap` / `setCaps` | 能力键、档位；`scope:"session"` + `sessionId` 时会话级 | 能力开关 |
| `setSessionRule` | `sessionId`, `kind`(sections/tools), `name`, `patch` | 会话级段 / 工具规则，`patch:null` 撤销 |
| `setBrief` | `enabled` | 保留简介总开关 |
| `aiSuggest` | `scope`(global/project/parts/session/item), `sessionId?`, `projectId?`, `modeId?`, `kind?`, `name?`, `focus?`, `impactScan?` | 生成 AI 建议；只读，不写配置。`impactScan` 缺省读 `state.ai.impactScan`；cache key=`scopeKey`+`fingerprint`，只接受服务端缓存引用 |
| `aiApply` | `suggestionId`, `itemIds[]`, `confirm`, `confirmBlocked?`, `allowSessionPrune?` | 全有或全无地应用服务端缓存的建议；返回新 `revision`、`undoToken`、`applied/skipped`；阻断项需显式 `confirmBlocked` |
| `aiUndo` | `undoToken` | 撤销一次 AI 应用；服务端校验 token 内的 `modeId`/`revision`/`scopeKey`，不匹配返回 `conflict`，不按当前 active mode 硬写 |

GET 不带 `action` 时返回完整 state；其中 `projected` 是「下一轮实际会发」的投影
（`total` / `sections` / `contexts` / `tools` / `removed` / `removedTokens`），
已按模式、项目/全局、会话规则和能力开关裁剪，概览与「少发」都读它，不再拿原始快照直接相加。

AI 动作的额外约束（0.6.0 规划）：

- 仅接受本机回环来源；校验 `Origin`/`Sec-Fetch-Site`，POST 带 CSRF token，按会话/动作限流；请求体大小上限与字段白名单，不提供任意文件读写参数。
- `aiSuggest` 在 `state.ai.enabled=false` 或 `state.ai.privacyAccepted=false` 时直接拒绝，说明「AI 建议默认关闭」；不回退到静默发送。
- 所有 AI 响应只返回服务端缓存的建议引用与摘要；客户端不能把任意 `items` 当已校验结果提交，`aiApply` 会重新校验作用域、类型、PROTECTED、fingerprint 与 `revision`。
- `aiApply` 成功后才递增 `revision`；失败不落盘、不递增，返回失败项与原因（`partial` 不会出现在写盘阶段）。
- 影响分析（`impactScan=on`）只做 advisory：`impacts` 不改变 `aiApply` 的允许集；`block` 项默认不勾选，进入应用前需 `confirmBlocked`。

### 2.9 客户端

- **Panel**：三个页签「构成 / 项目 / 全局」；顶部是 `position:sticky` 的仪表条，显示本次请求 ≈token、三段比例尺（系统内容 / 运行时注入 / 工具定义）与图例；内容区 `max-width:1120px`、左右 26px。
- **ComposerChip**：输入框左侧胶囊，默认显示 `上下文 Nk ▾`；`aria-haspopup="dialog"`、`aria-expanded` 随浮层状态变化。
  - 打开时 `load()`；每 12s 轮询一次；`focus`、`visibilitychange`、关闭浮层时各刷新一次。
  - 浮层：`position:fixed`，宽度 `min(430px, 100vw - 24px)`，底边贴输入框上方 10px，左右至少 12px；`maxHeight` 为视口可用高度的 240–560px；高度在「概览」页测量后固定，且至少 520px，切到短列表不缩高。
  - 骨架：页头（标题 + 刷新/关闭）→ 页签行（38px 固定、单行横向滚动）→ 页头行（30px，仅非概览页）→ 共享工具栏（筛选框 + 全开/全关）→ 内容区（`flex:1 1 0`，独立纵向滚动）→ 概览页脚（写入输入框 / 立即压缩）。
  - 六个页签：概览、技能、MCP、插件、提示段、工具。页签 badge 显示条目数；提示段/工具显示「生效/总数」。
  - 概览页不显示 30px 页头行；汇总条固定三个数「当前窗口 / 每次重发 ≈ / 下一轮预计 ≈」，前面是「i」说明按钮：鼠标悬停、触摸点击展开，移开或点别处关闭。
  - 技能/MCP/插件、提示段、工具页的开关写的都是**本会话层**；有会话覆盖时行内标「本会话」，页头说明显示「本会话 · 继承项目 X · n/N 已加载/生效」；撤销只清会话覆盖。
  - 0.5.26 起，全局筛选框与「全开 / 全关」在同一行 `.cc-pop-toolbar`：筛选框在左（内置 ×），按钮在右（仅技能/MCP/插件页显示）；提示段/工具页只有筛选框。筛选作用于除概览外的五页，切页保留，点 ×、关闭浮层或按全局 `Esc` 清空（筛选框内 `Esc` 只清词）；全开/全关仍作用于整组，不受筛选影响。
  - 0.5.28 起，所有筛选框旁增加状态下拉「全部状态 / 已开启 / 已关闭」，与文本搜索叠加；能力页按当前档位判断，提示段/工具按「规则 enabled 且所属能力为 on」的实际生效判断；浮层切页保留，面板切子页重置。
  - 提示段/工具页只做开关，正文改写仍在左侧项目页；工具所属能力被关掉时开关置灰并标「简介 / 隐藏」。
  - 0.5.15 起这两页计数按「实际发不发」算：`enabled && 能力为 on` 才计入生效，标题显示「x/N 生效 · 少发 ≈Y」，页签 badge 也显示 `x/N`。
  - 「上次压缩」用 `compactSummary(info)` 生成固定文案：`上次压缩：折叠 X tokens，窗口 A → B（少 C）`；自动触发追加「（自动）」；失败显示真实错误。
  - 空态：技能/MCP/插件「这一类还没有可配置的条目。」，筛选无结果「没有匹配的条目。」，提示段/工具「没有匹配的内容。」。
- **自动压缩设置**：概览页底部勾选框 + 数字输入（5–95），`onBlur` 提交 `setAutoCompact`；越界值按 5 或 95 显示并提交。
- **视觉与无障碍**：颜色全部走 `--dsw-alias-*` 宿主变量并带 fallback；`focus-visible` 2px 外描边；浮层 `role="dialog"`、页签 `role="tab"`/`aria-selected`；减少动画偏好下关闭 `cc-rise` 动画。

## 三、后续迭代方向

### P0（下一版优先）

1. **压缩结果与 DSH 原生窗口严格对齐**
   - 现状：胶囊用 `pressureTokens`，DSH 状态栏可能用另一个采样点，极端情况下差几 k。
   - 做法：统一读同一个 `contextPressure()` 快照，并在结果里记录采样时刻。
   - 验收：同一时刻胶囊与状态栏差值 ≤ 1%。

2. **自动压缩的会话级策略与冷却**
   - 现状：全局一个阈值，压完可能很快又到阈值。
   - 做法：每个会话记录 `lastAutoAt`，冷却 5 分钟；连续自动压缩超过 3 次/小时则暂停并提示。
   - 验收：不会出现「压完立刻再压」的抖动。

3. **失败原因结构化**
   - 现状：错误是拼接字符串。
   - 做法：`{code, message, cause, via}`，UI 按 code 给建议（权限/忙/无区间/服务缺失）。
   - 验收：每种失败都有可操作提示。

### P1（近期）

4. **压缩历史与趋势**
   - 保留最近 20 次记录（时间、原因、前后窗口、折叠量），胶囊里画一条迷你曲线。
   - 解决「上次压缩」只有一条、多个会话互相覆盖的问题。

5. **重复系统消息识别**
   - 统计 `system/message` 的 append/replace 比例，提示「本次因规则变化多发了 N tokens」。
   - 长期：规则变更合并到一次生效，减少 append。

6. **能力开关的生效验证**
   - 下一轮请求后对比实际提示词与预期，给出「已生效 / 被其他层覆盖」。
   - 解决「关了但看起来没关」的信任问题。

7. **项目匹配可视化**
   - 胶囊里显示「当前项目：X（继承自 Y）」，可一键跳到项目页。
   - 处理 cwd 变更、软链接、大小写差异。

### P2（中期）

8. **压缩策略可选**：保留最近 N tokens、按模块优先级折叠、保留工具结果摘要。
9. **成本估算**：按模型单价折算每次请求/每次压缩的金额。
10. **多会话总览**：所有活跃会话的窗口压力排行榜，支持批量压缩。
11. **导出报告**：一次会话的上下文账单（Markdown / CSV）。
12. **工程化**：`lib/` 单测（store 消毒、继承链、capKey）、类型定义、错误码表。

### 风险与依赖

- 宿主内部 API（`runMaintenance`、`turnBoundaryOf`、`agentPresets.serviceFor`）不是公开契约，升级需回归；已做存在性判断与命令回退。
- 客户端 bundle 更新依赖页面刷新；后续可加版本号提示。
- 压缩本身有不可逆性（历史被 shadow），UI 文案要明确「折叠后模型看不到原文」。

## 附录 B：术语

| 术语 | 含义 |
| --- | --- |
| 能力键 capKey | `skill:` / `mcp:` / `plugin:` 前缀的最小开关单位 |
| 档位 | 加载 / 简介 / 隐藏 |
| 窗口表面 surface | 这一轮真正进入模型的有效 token（历史尾部） |
| 折叠 shadow | 压缩后被隐藏、模型不再看到的历史 |
| 排队 | 忙时把压缩请求存起来，`turn/end` 或轮询时补跑 |
| 保留简介 brief | 删掉完整定义，只留一行说明 |
